Gideon — это персональный ИИ-агент, который работает на вашей собственной машине. Один процесс обслуживает веб-консоль и выполняет работу: чат, длительные циклы достижения целей, память, база знаний, задачи, расписания, входящие и платформа приложений с управлением разрешениями.

Он создан для одного человека, который хочет агента с реальным доступом к своему собственному компьютеру и своим сервисам, не отдавая ключи хостинговому продукту. Состояние хранится в директории, которую вы выбираете. Провайдеры моделей подключаемы: ключ Anthropic или OpenAI, OpenAI-совместимая конечная точка, учётные данные AWS Bedrock или модель, запущенная локально.

> **До 1.0:** Gideon находится на версии **v0.1.3**. Он развивается быстро, и выпуск может что-то сломать. Запустите `gideon snapshot` перед обновлением и прочитайте [CHANGELOG.md](CHANGELOG.md), чтобы узнать, что вошло в релиз.

## Что он умеет

- **Общайтесь с ним или передавайте ему работу.** Сессии чата с потоковыми ответами, вызовами инструментов, артефактами и стенограммой, по которой можно искать. Субагенты берут задание и отчитываются, пока вы продолжаете работать.
- **Позвольте ему работать без присмотра.** Циклы прорабатывают цель на протяжении множества ходов по расписанию. Задачи, триггеры и рабочие процессы превращают разовые запросы во что-то воспроизводимое.
- **Дайте ему память.** Многоуровневая память сохраняет предпочтения и контекст между разговорами. База знаний хранит документы, на которые вы укажете, поэтому ответы ссылаются на ваши материалы, а не на открытый интернет.
- **Оставайтесь в курсе.** Входящие собирают то, что требует вашего внимания, из таких каналов, как Slack, а также от самого Gideon. Голосовой ввод и озвученные ответы — опциональные дополнения.
- **Расширяйте его.** Платформа приложений и её Python SDK (`gideon.sdk`) охватывают модели, каналы, поиск, инструменты и дашборды. Навыки, промпты и серверы MCP добавляют возможности, не затрагивая ядро.
- **Решайте, к чему он может получить доступ.** Подтверждения использования инструментов, разрешения для каждого приложения, работа с учётными данными, проверка команд и журнал аудита. Ядро не зависит от провайдера: интеграции живут в приложениях, а не в базовом пакете.
- **Наблюдайте за его работой.** Консоль показывает сессии, активность, выполняющиеся циклы, запланированные задания и состояние системы, а также терминал для машины, на которой работает Gideon.

## Требования

- Python 3.12 или новее.
- Node.js 22.12 или новее с npm, если вы хотите собрать консоль из исходников. CI собирает консоль на Node 24.
- macOS или Linux. В Windows используйте путь через Docker Compose в [docs/guides/CONTAINERS.md](docs/guides/CONTAINERS.md).
- Провайдер моделей для всего, что работает на моделях, настраивается после первого запуска. Локальная модель тоже подойдёт.

Внешней базы данных и брокера сообщений нет. Всё работает в одном процессе шлюза.

## Запуск из репозитория

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
npm ci
npm run build

export GIDEON_HOME="$PWD/.dev-home"
.venv/bin/gideon setup
.venv/bin/gideon gateway --no-open --port 10000
```

Откройте адрес консоли, который выведет шлюз. `npm run build` записывает консоль в `apps/console/dist`, откуда шлюз отдаёт её прямо из репозитория. `gideon setup` запрашивает директорию рабочего пространства и часовой пояс. Провайдеры моделей настраиваются после этого, в консоли, поскольку в новом домашнем каталоге ещё нет приложения-провайдера, которое могло бы хранить учётные данные.

`GIDEON_HOME` — это директория, в которой хранятся конфигурация, учётные данные, разговоры и прочее состояние времени выполнения. Без неё Gideon использует `~/.gideon`. Сохранение изолированного значения `.dev-home` во время экспериментов сделано намеренно: это удерживает экземпляр для разработки в стороне от вашего реального. Остановите шлюз, работающий на переднем плане, с помощью Ctrl-C.

Если же вам нужна установка из пакета, `sh infrastructure/website/install.sh` выполняет начальную установку с помощью `uv`. Чтобы проверить байты этого установщика перед запуском, см. [Проверка однострочника](docs/guides/GETTING_STARTED.md#verify-the-one-liner). Полное руководство — от полностью чистой системы до первого чата — находится в [docs/guides/GETTING_STARTED.md](docs/guides/GETTING_STARTED.md).

## Разработка

```sh
.venv/bin/python -m pip install -e '.[test]'
sh tooling/scripts/install_git_hooks.sh
```

Скрипт-хук форматирует подготовленный к коммиту Python-код и подписывает ваши коммиты, что и проверяет CI. `npm install` не устанавливает хуки.

| Команда | Что делает |
| --- | --- |
| `make format` | Форматирование Python с помощью black и isort |
| `make lint` | black, isort, flake8 и mypy по runtime и проверкам |
| `make test` | Запуск набора тестов Python (`checks/runtime`) |
| `make serve` | Сборка консоли и запуск шлюза с `.dev-home` |
| `make serve-web` | Запуск сервера разработки консоли на порту 3100 с подключением к шлюзу |
| `npm run typecheck:web` | Проверка типов консоли |
| `npm run test:web` | Тесты консоли с помощью Vitest |
| `make test-e2e` | Проверки взаимодействия в Chromium |
| `make docker-up` | Запуск стека контейнеров из `infrastructure/compose` |

[CONTRIBUTING.md](CONTRIBUTING.md) описывает рабочие договорённости, подпись DCO и то, как изменения классифицируются и проверяются.

## Статус

Gideon находится в стадии до 1.0 и активно развивается. Шлюз, консоль, оболочки для десктопа и мобильных устройств, клиент Python и проверки, которые их задействуют, — всё это есть в репозитории, и CI запускает набор тестов Python, тесты консоли и проверки взаимодействия при каждом изменении.

Чего это не означает: хостингового сервиса не существует, и этот репозиторий не предполагает ни опубликованного пакета, ни конечной точки релизов, пока вы не направите `GIDEON_RELEASE_REPOSITORY` на неё. Интеграциям нужны собственная конфигурация, учётные данные и поддержка платформы. Некоторые возможности в репозитории не были проверены сквозным образом на живом провайдере. Проходящие проверки говорят что-то о том, что они покрывают, и ничего — об остальном.

## Безопасность

Gideon читает локальные файлы, запускает инструменты и общается с сервисами, которые вы настроили, поэтому токен шлюза и учётная запись, под которой он работает, дают реальный доступ. Сообщения об уязвимостях передаются по приватному каналу тому, кто предоставил вам этот репозиторий. См. [SECURITY.md](SECURITY.md).

Gideon не отправляет телеметрию. Ничто о вашем использовании не покидает вашу машину, если вы не настроите интеграцию, которая это делает.
